# Правила вызова утилиты __analyzer__, формат её командной строки и приёмы её использования.

1. **Командная строка утилиты __analizer__.**


	analyzer [--ts-path | -t TreeSitterPath] [--ts-config_path | -c TreeSitterConfigPath] [--file-path | -p FilePathPrefix] (--file | -f) File [File ...]


* *TreeSitterPath* - полное имя исполняемого файла программы __tree-sitter__, вызываемой из analyzer 	для её внутренних нужд.
* *TreeSitterConfigPath* - полное имя файла конфигурации программы __tree-sitter__, которая будет 	передаваться __tree-sitter'у__ при вызове. 
* *FilePathPrefix* - общий префикс путей всех обрабатываемых файлов *File*. 
* *File...* - перечисление (набор) целевых файлов, которые будут обработаны анализатором. Указание хотя бы одного такого файла обязательно.


Для получения краткой помощи по формату командной строки программы её можно вызвать так:

    analyzer [--help | -h]

Наличие в командной строке параметра *--help* выводит на консоль сжатое описание формата вызова утилиты. Все прочие параметры (если они указаны в командной строке)
при этом игнорируются.

2. **Описание назначения отдельных параметров командной строки и настройки среды окружения утилиты __analyzer__.**

Утилиты __analyzer__ не является полностью автономной и использует в процессе своей работы внешнюю программы __tree-sitter__, а также файл её конфигурации. Поэтому для своей правильной
работы она нуждается в информации о местоположении этих двух объектов, которые должны существовать, быть работоспособны и корректно составлены.

Полное имя исполняемого файла программы __tree-sitter__ может быть передано утилите через параметр командной строки *--ts-path*, посредством переменной окружения **TREE-SITTER**,
а также этот модуль может быть найден утилитой самостоятельно, если он имеет определенное имя (__tree-sitter.exe__ для Windows и __tree-sitter__ для прочих платформ) и доступен через **PATH**.
Параметр командной строки, если он указан, имеет высший приоритет, при его неверном содержимом работа программы прекращается. Прочие два варианта используются, если параметр *--ts-path*
отсутствует.

Полное имя конфигурационного файла можно указать посредством параметра *--ts-config_path* или переменной окружения **TREE-SITTER-CFG**. Параметр командной строки также имеет преимущество,
при его некорректном содержимом работы программы завершается ошибкой. При отсутствии обоих типов указания положения файла конфигурации, программа пытается обнаружить такой файл (со
стандартным именем *config.json*) по месту расположения исполняемого файла самой утилиты __analyzer__, а также в каталоге найденного на предыдущем этапе исполняемого файла
__tree-sitter[.exe]__.

Если все обрабатываемые файлы расположены в одном каталоге (или его подкаталогах), пути к ним можно упростить указанием аргумента *FilePathPrefix* параметра *--file-path*. При наличии
этот префикс будет автоматически приставляться ко всякому имени <File> файлов-целей из списка аргументов параметра *--file*. Если все целевые файлы расположены там же, где и исполняемый файл
данной программы __analyzer__, можно использовать следующий формат параметра *--file-path*:

	--file-path $$$_EXE

Если же все целевые файлы размещены в одном каталоге с __tree-sitter[.exe]__, то можно применить такой макрос:

	--file-path $$$_TREE_SITTER

При отсутствии параметра *--file-path* имена *File* должны быть полными или заданы относительно текущего каталога файловой системы.

Самый простой способ обеспечить работоспособность программы - установка двух переменных среды окружения - **TREE-SITTER** с полным именем исполняемого файла __tree-sitter[.exe]__ и
**TREE-SITTER-CFG** с полным именем конфигурационного файла. Его можно также разместить в одном каталоге с __tree-sitter[.exe]__. Там он будет найден автоматически.

3. **Модульные тесты.**

Модульные тесты также нуждаются в той же базовой информации, что и основная программа - маршрут исполняемого файла программы __tree-sitter__ и её конфигурационного файла.
Так как модульные тесты не предполагают наличия командной строки, то наиболее простым и надёжным методом обеспечения их работоспособности будет создание те же двух переменных среды
окружения - **TREE-SITTER** и **TREE-SITTER-CFG**. Эти переменные должны содержать полные квалифицированные имена исполняемого файла программы __tree-sitter__ и её конфигурационного файла
(обычно он имеет имя "config.json") соответственно.

Существуют также и некоторые автоматические способы их поиска, но они сейчас ненадёжны и описываться здесь не будут. Отмечу только, что должен также быть автоматически обнаружен
файл конфигурации __tree-sitter'а__, если он имеет стандартное имя *config.json* и находится в одном каталоге с исполняемым модулем "древолаза".
